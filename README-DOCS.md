# CarWashApp — Архитектура

## Обзор

CarWashApp — это модульная SaaS-платформа для управления автомойками, построенная на Flutter (фронты) и NestJS + PostgreSQL (бэкенд). Система предназначена для автоматизации процесса бронирования, оплаты, контроля загрузки и аналитики бизнеса.

Система разделена на 4 основных модуля:

- **Client** — мобильное приложение для клиентов (бронирование, оплата, уведомления)
- **Admin** — веб-интерфейс для администраторов (управление записями, сменами, кассой)
- **Washer** — мобильное приложение для мойщиков (контроль смен, загрузка, оплата)
- **Owner** — панель управления для владельцев (аналитика, финансы, персонал, подозрительные события)

Все модули взаимодействуют с единым бэкендом, который обеспечивает:
- аутентификацию и авторизацию
- управление данными (база данных)
- реальное время (WebSocket)
- автоматизированные задачи (Cron)

## Архитектура бэкенда

### Стек
- **NestJS** — фреймворк Node.js (TypeScript) для построения REST API и микросервисов
- **Prisma ORM** — ORM для PostgreSQL с генерацией типизированных клиентов
- **PostgreSQL** — основная база данных с поддержкой JSONB, enum, транзакций
- **WebSocket (NestJS Gateway)** — для реального времени (обновления бронирований, смен, уведомлений)
- **Cron (NestJS Schedule)** — для автоматических задач (истечение оплаты, завершение смен, очистка)
- **Docker** — контейнеризация бэкенда и БД

### Модули бэкенда

| Модуль | Описание |
|--------|----------|
| `api/` | Основной REST API (NestJS) |
| `prisma/` | Схема базы данных и миграции |
| `src/` | Логика приложения (сервисы, контроллеры, DTO) |
| `gateways/` | WebSocket-шлюзы для реального времени |
| `scheduler/` | Cron-задачи |

### База данных (Prisma)

База данных спроектирована как **многотенантная (multi-tenant)** с поддержкой:
- нескольких локаций (мойки)
- пользователей с ролями (Client, Admin, Washer, Owner)
- бронирований с привязкой к локации, посту, клиенту, услуге
- платежей (наличные, карта, контракт)
- смен (Shift) с кассовыми событиями
- планируемых графиков (PlannedShift)
- оплаты мойщикам (WasherPayRule)
- аудита действий (AuditEvent)
- уведомлений владельцу (OwnerAlert)
- waitlist (очереди)

Ключевые сущности:
- `Location` — автомойка
- `User` — пользователь (роль: ADMIN, WASHER, OWNER)
- `Booking` — бронирование (связь с `Car`, `Service`, `Client`, `Shift`)
- `Payment` — оплата (тип: DEPOSIT, REMAINING, REFUND)
- `Shift` — смена администратора (открыта/закрыта)
- `ShiftCashEvent` — операции с кассой (открытие, закрытие, внесение)
- `PlannedShift` — запланированная смена (для планирования)
- `WasherPayRule` — правила выплат мойщикам (проценты по типу услуги)
- `AuditEvent` — лог всех изменений (для аудита и безопасности)
- `OwnerAlert` — уведомления владельцу (о подозрительных действиях, несоответствиях)

## Архитектура фронтендов (Flutter)

Все фронтенды построены на **Flutter** и используют единый API-клиент, работающий через HTTPS и WebSocket.

### Общие принципы
- **Модульность**: каждый модуль (Client, Admin, Washer, Owner) — отдельный Flutter-проект
- **Разделение логики**: `core/` — общие сервисы, модели, API-клиенты; `features/` — экраны и UI
- **Реальное время**: WebSocket-подключение для мгновенного обновления UI (например, при изменении статуса бронирования)
- **Кэширование**: локальное хранение данных (например, список клиентов, услуг) для офлайн-доступа
- **Безопасность**: токены доступа, HTTPS, проверка ролей на клиенте и сервере

### Модули фронтенда

#### 1. Client Module
- **Цель**: клиентская запись на мойку
- **Ключевые экраны**:
  - `CreateBookingPage` — выбор даты, времени, услуги, оплата
  - `PaymentPage` — выбор способа оплаты (карта, наличные)
  - `BookingsPage` — история и текущие записи
  - `WaitlistPage` — очередь ожидания
- **Особенности**:
  - Автоматическое подбор времени (с учетом занятости постов)
  - Поддержка waitlist при закрытых постах
  - Свайп-интерфейс для выбора авто
  - Отображение бонусов администраторов (в виде скидок)

#### 2. Admin Module
- **Цель**: управление записями, сменами, кассой
- **Ключевые экраны**:
  - `BookingListPage` — список всех записей
  - `BookingActionsSheet` — действия с записью (перенос, отмена, оплата, фото)
  - `ShiftManagementPage` — открытие/закрытие смены, кассовые операции
  - `ClientListPage` — управление клиентами (блокировка, поиск)
- **Особенности**:
  - Добавление фото до/после мойки
  - Учет бонусов за продажу и upsell
  - Поддержка cash drawer (открытие/закрытие кассы)
  - Фиксация действий в AuditEvent

#### 3. Washer Module
- **Цель**: управление сменой, фиксация времени работы, расчет зарплаты
- **Ключевые экраны**:
  - `ShiftClockPage` — вход/выход на смену
  - `AssignedBookingsPage` — список назначенных бронирований
  - `PayrollSummaryPage` — расчет заработка за смену
- **Особенности**:
  - Фиксация времени работы через `WasherClockEvent`
  - Расчет зарплаты на основе `WasherPayRule` (проценты от услуги)
  - Привязка к конкретному посту (Bay)

#### 4. Owner Module
- **Цель**: аналитика бизнеса, контроль персонала, финансовая отчетность
- **Ключевые экраны**:
  - `OwnerDashboardTab` — главная панель (график, сводка, уведомления)
  - `EmployeesPage` — управление администраторами и мойщиками
  - `ServicesPage` — управление услугами и ценами
  - `SettingsPage` — настройки связи, уведомлений, компенсаций
  - `SuspiciousEventsPage` — детализация подозрительных действий
- **Особенности**:
  - Графики выручки и подозрительных событий
  - Уведомления о сомнительных действиях (скидки, отмены, закрытие постов)
  - Гибкие правила оплаты персоналу (проценты, оклады)
  - Интеграция с Telegram/WhatsApp для уведомлений

## Связи между модулями

- Все модули используют **один и тот же API-эндпоинт** (`/api`)
- Аутентификация через `x-user-id` и `x-shift-id` в заголовках
- Реальное время через WebSocket (`/bookings` — события бронирований)
- Данные о локации и пользователе передаются через `locationId` и `userId`
- Все изменения логируются в `AuditEvent` (кто, что, когда, почему)

## Масштабируемость

- **Многотенантность**: каждая мойка — отдельная `Location` с собственными пользователями, услугами, графиками
- **Контейнеризация**: бэкенд и БД — в Docker, легко развертываются на Kubernetes
- **Горизонтальное масштабирование**: API-сервисы могут масштабироваться независимо
- **База данных**: PostgreSQL поддерживает репликацию и шардинг

## Безопасность

- **Ролевая модель**: каждый пользователь имеет роль, и доступ к данным ограничен по ней
- **Аудит**: все действия логируются (даже удаление бронирования)
- **Ограничения на клиенте**: UI не позволяет выполнять действия без прав
- **Проверка на сервере**: все запросы проверяются на права доступа
- **Шифрование**: пароли хранятся в виде `scrypt`-хешей
- **Валидация**: все входные данные валидируются на сервере

## Заключение

CarWashApp — это **не просто приложение**, а **целая экосистема** для управления автомойкой. Каждый модуль — это **отдельный продукт**, который работает в единой системе. Это позволяет:

- **Масштабировать** — добавлять новые мойки без переделки кода
- **Управлять** — контролировать каждый этап процесса
- **Анализировать** — видеть, где теряются деньги
- **Автоматизировать** — убирать рутину
- **Монетизировать** — продавать как SaaS или франшизу

> Это — не код. Это — **бизнес-процесс, закодированный в программу**
